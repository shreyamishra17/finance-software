==================================================================
1. FIRESTORE  (the structured database — accounts, transactions, etc.)
==================================================================
Database name : finance-database     (IMPORTANT: it is NAMED, not "(default)")
Location      : nam5  (US multi-region)
Type          : Firestore Native
Console       : Firebase console -> Build -> Firestore Database
                (or Cloud console -> Firestore -> select "finance-database")

Data is organized PER USER. Every user has one document under "users",
and their data hangs off it as subcollections:

  users/{uid}                          <- one document per signed-in user
    |
    +-- accounts/{account_id}          bank/credit account records
    |     fields: account_type, account_balance, investment_balance,
    |             needs_login, has_credentials, last_url, ...
    |
    +-- transactions/{txn_id}          individual transactions for that user
    |
    +-- credentials/{...}              bank login secrets for auto-fetching
    |                                  (sensitive — encrypted before storage)
    |
    +-- _meta/counters                 internal ID counters (next account id, etc.)

  {uid} = the Firebase Auth user id (see section 3).

==================================================================
2. FIREBASE STORAGE  (the file bucket — raw PDFs + processed CSVs)
==================================================================
Bucket   : financesoftware-487822.firebasestorage.app
Location : US-EAST1
Console  : Firebase console -> Build -> Storage
CLI      : gcloud storage ls gs://financesoftware-487822.firebasestorage.app

Files are organized per user, by a "user slug". Layout:

  {user_slug}/raw/{period}_{account_id}_{source}.pdf
        -> the original uploaded bank-statement PDFs (kept as-is)

  {user_slug}/processed/acc_{account_id}.csv
        -> the cleaned/parsed transactions for that account, appended over time

So: Firestore holds the structured records; Storage holds the original PDF
documents and their processed CSV exports.

(Note on the transaction-categorizer ML model: the model directory
categorizer/models/ is gitignored, so the CI-built image does NOT contain
the BERT model. When the model is absent the categorizer falls back to the
rule-based / rapidfuzz path (it does NOT crash). The code can also fetch the
model from GCS via CATEGORIZER_MODEL_GCS_URI, but that env var is not set, so
no model bucket is in use. This was true on the old project too — unchanged
by the move to 487822.)
